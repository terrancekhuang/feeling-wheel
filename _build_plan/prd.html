Feeling Wheel

Working name. It's a placeholder and easy to change before launch.

A free, installable web app where Christians name what they're feeling on a 3-ring wheel of negative emotions. Each emotion opens Scripture (BSB) that first sits with the feeling, then offers truth, and ends with a gentle next step (a question, a prayer, an action). It works offline, and every emotion has its own shareable link.

This is a free public ministry focused on the individual Christian's daily walk. There's no monetization, no accounts, and no saved user data. Naming a feeling precisely is part of the value, as the Psalms model. The content follows one rule: meet the emotion before correcting it, and never answer pain with a dismissive proof-text. Curation quality is the product. AI drafts the taxonomy and verse sets, and the author reviews every entry before it ships.

It's a fully static app: plain files with no server, hosted free on Cloudflare Pages. All content lives in one bundled data file. The build runs in 5 milestones. Milestones 1–3 build the app around one fully curated branch (Fear), milestone 4 curates the remaining branches, and milestone 5 launches it publicly.

React Vite Tailwind CSS D3 (zoomable sunburst, SVG) Installable PWA, offline Cloudflare Pages Berean Standard Bible (public domain)

What the app does

  • Emotion wheel

    A 3-ring zoomable sunburst with about 6 core, 30 middle and 80–100 specific negative emotions. Tap to go deeper, and tap the centre to go back.

  • Emotion page

    Every emotion at every ring has three groups: God sees this, Truth to hold, and A next step (a question, a prayer and an action).

  • Sharing

    A clean link for each emotion (/anxious), a native share button, and one-tap copy of any verse with its reference.

  • Crisis banner

    Flagged emotions show a gentle banner that can't be dismissed, with a tap-to-call 988 button and a link to a global helpline directory.

  • Installable and offline

    Add to home screen. After the first visit, everything works with no signal.

  • Content file with review gate

    Only entries the author has marked as reviewed go live. A content check verifies the BSB text and blocks bad publishes.

  • About page

    Why it exists, how to use it, a "not a substitute for help" note, BSB attribution and a contact email.

Starting point

This is an empty project with no starter template. Milestone 1 sets up the app from scratch. A login-based starter would be the wrong fit, because there are no accounts, no database and no server.

Out of scope (v1)

  • Positive emotions (joy, gratitude, peace) — v1 focuses on meeting people in hard feelings. This is a possible later addition.
  • Search ("type what you feel") — the wheel is the way in. Search is a possible later addition.
  • Favourites or emotion history — v1 saves no user data, either on the device or synced.
  • Verse memorization — a separate product loop, left for later.
  • Verse-image sharing cards — copying the text and sharing the link cover v1.
  • Native mobile apps / app-store listings — the installable web app covers phones.
  • CMS or admin screen — the author edits the content file directly.
  • Other Bible translations and other languages — BSB only, in English. One translation keeps the curation manageable.
  • Analytics of any kind — private by default, with no tracking or counters.
  • Accounts, notifications, daily reminders — no backend, and v1 doesn't need any of them.

External services

The app doesn't call any outside service while it runs. No API keys are needed.

Milestones

1

Taxonomy + Wheel

Set up the app, draft the full original 3-ring emotion taxonomy, and make the zoomable wheel work with it, so the author can click through every emotion and review the tree.

What gets built

  • A proposed visual style that the author approves before the rest of the build. It should be calm, warm and readable, with light and dark modes that follow the phone setting.
  • The content file with an AI-drafted, original taxonomy: about 6 core, about 30 middle and about 80–100 specific negative emotions. Each has a name, link slug, parent, a one-line description and a suggested crisis flag. All are marked as not reviewed. It's inspired by the feelings-wheel concept but doesn't copy any published graphic.
  • The main screen, with the heading "What are you feeling?" and the hint "Not sure? Tap the closest one; you can go deeper."
  • A zoomable sunburst wheel that shows the current level plus one ring out. Slices are coloured by core family, with lighter shades further out. Tapping a slice zooms it to the centre and reveals its children.
  • The centre circle shows the current emotion's name and a "Read verses" button, and tapping the centre zooms back out. In this milestone, "Read verses" and taps on specific emotions go to a placeholder page.
  • The wheel works the same on phone and desktop, with keyboard navigation and labels for screen readers.

Not in this milestone

  • Any verses, prayers or real emotion pages
  • The review gate or content check (everything shows for now)
  • Sharing, offline/install, the About page, and deploying
  • A list view, search, extra animations, a "feeling of the day", and showing all three rings at once on mobile

Done when: On both phone and desktop, the author can open the app locally, zoom from any core emotion down to any specific emotion and back, and read the full drafted taxonomy. They can also edit a name in the content file and see the change on the wheel.

2

Fear Branch + Emotion Page

Fully draft the Fear branch's content, build the emotion page, and add the review gate and content check, so the author can review real pages in context.

What gets built

  • AI-drafted content for every emotion in the Fear branch (core, middle and specific): God sees this, Truth to hold, a reflection question, a prayer and an action. Verse text comes from the official BSB. Lament comes before correction, with no dismissive proof-texts.
  • The emotion page, top to bottom: a tappable breadcrumb (Fear › Worried › Anxious), the name and description, the crisis banner if flagged, God sees this (2–4 verse cards), Truth to hold (2–4 verse cards), and A next step (the question, prayer and action, each labelled). Core and middle emotions also get "Go deeper" chips linking to their children. There's a back-to-wheel button.
  • Verse cards show the BSB text and reference only, plus a copy icon that copies "verse text" — Psalm 42:5 (BSB) and briefly shows "Copied".
  • The crisis banner appears on every crisis-flagged emotion, above the verses, and can't be dismissed. It has gentle wording, a tap-to-call 988 button (call or text), an "Outside the US? Find a helpline" link to findahelpline.com, and the line "If you're in immediate danger, call your local emergency number."
  • Review gate in the live build: an emotion appears on the wheel only if it, or something beneath it, is reviewed. Its own page shows content only if it's reviewed. Unreviewed links show "This page is still being prepared" with a link back to the wheel.
  • A draft preview mode on the author's computer shows everything, with a visible DRAFT badge on unreviewed pages.
  • A content check the author can run. It flags verse text that doesn't exactly match the BSB, missing groups, prayers or actions, verse counts outside 2–4, and duplicate or broken links. It also reports "X of Y emotions reviewed".

Not in this milestone

  • Content for any branch other than Fear
  • Marking entries as reviewed. Only the author does that, by hand.
  • The share button, link previews, offline/install, the About page, and deploying
  • The surrounding passage, external Bible links, audio, notes, favourites, and switching translations
  • Crisis detection from user input, automatic contact, chat, and country auto-detection
  • An in-app editing screen, multiple authors, review history, and scheduled publishing

Done when: In draft preview, the author can open any Fear emotion and read its full page, copy a verse, and see the crisis banner on a flagged emotion. The content check passes on the Fear branch. After the author marks a few emotions as reviewed, the normal build shows only those (and the path to them), and the rest show "still being prepared".

3

Share, Offline & Soft Launch

Make the app shareable, installable and fully offline, add the About page, and put it online privately on Cloudflare Pages.

What gets built

  • Every emotion's clean link (site/anxious) opens straight to its page, including on a first visit or a refresh.
  • A Share button on emotion pages opens the phone's share sheet, or copies the link on desktop.
  • Pasting a link into a chat app shows a tidy preview with the emotion's name and description.
  • Installable on phones (Add to Home Screen) and desktop browsers. It opens full screen with its own icon and splash colour.
  • After the first visit, the wheel, every emotion page and every verse work with no internet. New content is picked up quietly on the next open, with an optional small "Updated" note.
  • An About page linked from a small footer on every page. It covers why the app exists, how to use it in 3 steps, the "devotional aid, not counselling or medical care" note with 988 and findahelpline.com, the BSB attribution, the fact that every entry is hand-reviewed, and a contact email.
  • Deployed to Cloudflare Pages at its free default address, showing reviewed content only. Publishing is blocked if the content check fails.

Not in this milestone

  • An "Install this app" prompt. The app relies on the browser's own install option.
  • Verse-image cards, custom social images, share counts, short links, and copying the whole page
  • Push notifications, background sync, and offline download-progress screens
  • An author bio, donation link, newsletter, statement of faith, and feedback form
  • A custom domain, final name, analytics, and public announcement

Done when: The author opens the live Cloudflare address on their phone, installs the app, and switches on airplane mode. The wheel and reviewed Fear pages still work. Sending a friend /anxious (once reviewed) opens straight to that page with a tidy preview.

4

Curate Remaining Branches

A repeatable content milestone. Each session drafts one remaining core branch to the same standard as Fear, and the author then reviews and marks entries as reviewed. Run it once per branch.

What gets built

  • Full drafted content for every emotion in the chosen branch, in all three groups, with exact BSB text
  • Crisis flags rechecked for that branch
  • Small taxonomy fixes the author asks for (renames, moves, merges) while reviewing
  • A short review list for the author covering each new emotion's link in draft preview, so nothing gets skipped

Not in this milestone

  • New app features or design changes
  • More than one branch per session
  • The agent marking anything as reviewed
  • Positive emotions

Done when: Every branch has full drafted content, the content check passes with no errors, and the author can walk through each branch in draft preview. Repeat until every branch is drafted and reviewed.

5

Public Launch

Final checks and polish, then make the app public.

What gets built

  • A full content check that passes, with every emotion reviewed
  • A launch checklist pass: every crisis-flagged emotion shows the banner, tap-to-call works on a real phone, offline works, every link opens and previews, and the app is readable in light and dark mode and with the keyboard and screen reader
  • Optional (recommended): a pastor or elder reviews the theology, using a printable list of every emotion and its content
  • Optional: the final app name, icon and a custom domain, if chosen by then
  • The production publish

Not in this milestone

  • Any feature from the out-of-scope list
  • Analytics, a marketing site, or app-store submission
  • New content beyond fixes found in review

Done when: The public address serves the complete, fully reviewed wheel. Every launch-checklist item is ticked, and the author is confident sending the link to anyone.
